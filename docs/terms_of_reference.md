# Многопоточность (QThread) — ключевой архитектурный раздел

## Кто в каком потоке живёт

| Поток | Объекты |
|---|---|
| GUI-поток (главный) | `QApplication`, `MainWindow`, `ActualIV`, `ControllerWidget`, `PSWidget`, `Graph`, `History`, `Session` |
| worker-поток `deviceThread` (`QThread`) | `Controller`, `K2636B`, `PS` |

Обоснование: обмен с приборами (pyvisa по USBTMC, последовательный порт МК) — блокирующие операции с таймаутами в секунды. Если выполнять их в GUI-потоке, интерфейс будет зависать. Поэтому всё железо и логика измерения выносятся в отдельный поток, создание — через `QThread` + `moveToThread()` (образец приёма — тестовый блок `if __name__ == "__main__":` в `reference/K2636B/K2636B.py`).

## Правила обмена между потоками

1. Между потоками — **только сигналы и слоты**. Прямой вызов метода объекта, живущего в другом потоке, запрещён (это гонка: метод исполнится в потоке вызывающего, а не владельца).
2. Все межпоточные соединения указываются явно с `Qt.ConnectionType.QueuedConnection` — сигнал кладётся в очередь событий потока-получателя и исполняется там.
3. Внутри worker-потока `Controller` вызывает методы `K2636B` и `PS` **напрямую** — это безопасно, потому что все трое живут в одном потоке и очередь событий одна.
4. GUI никогда не вызывает `K2636B` / `PS` напрямую — только через сигналы контроллеру (а контроллер уже решает, что делать с железом). Исключение: подписка виджетов на *сигналы-уведомления* драйверов (например `ActualIV` слушает `K2636B.newIV_A`) — подписка на сигнал это не вызов, это разрешено.
5. Данные между потоками передаются копиями в аргументах сигналов (float, tuple, dict простых типов). Разделяемых изменяемых структур между потоками быть не должно; если понадобятся — только под `QReadWriteLock` (как в старом каркасе).

## Неблокирующий цикл измерения (обязательная механика)

Цикл развёртки **событийный, а не while-цикл**:

1. `Controller` выполняет одну точку развёртки (set_voltage → выдержка → get_iv → emit точки).
2. Затем перепланирует себя: эмитит внутренний сигнал `sig_next_point`, соединённый со слотом `next_point` через `Qt.ConnectionType.QueuedConnection`.
3. Так цикл крутится внутри очереди событий worker-потока, и слоты `pause` / `stop` успевают обрабатываться между точками.

Запрещено: `while`-цикл по всем точкам и `time.sleep()` в логике развёртки — они заблокируют worker-поток, и кнопки pause/stop перестанут работать. Задержка реализуется через `QTimer`, живущий в worker-потоке: срабатывание таймера = измерение точки.

## Семантика временного шага Δt (delay)

1. Существует одна задержка delay: она стартует сразу после измерения точки (get_iv) и отсрочивает следующее измерение.
2. Её назначение — покрыть время установления нового напряжения: в течение delay контроллер выставляет следующее напряжение, и оно успевает установиться на образце до get_iv.
3. Время установления напряжения заранее НЕИЗВЕСТНО (зависит от прибора, кабелей, образца; программно не измеряется), поэтому delay задаётся пользователем С ЗАПАСОМ.
4. Механика: задержка реализуется QTimer в worker-потоке (sleep запрещён); между get_iv и следующим set_voltage паузы нет — напряжение выставляется в начале delay, чтобы settle шёл весь интервал.
5. Первая точка развёртки и первая точка после resume: измерение через delay после set_voltage — предыдущего измерения нет, задержка работает так же.

## Запуск потоков (в main.py)

1. Создать `QApplication`.
2. Создать `deviceThread = QThread()`, создать `Controller`, `K2636B`, `PS` без родителя, `moveToThread(deviceThread)`.
3. Создать `MainWindow` и виджеты (в GUI-потоке).
4. Выстроить все связи signal/slot (таблица связей — в разделе каждого блока; сводную карту вести в `docs/signals_scheme.md` для нового проекта).
5. `deviceThread.start()`.
6. Открытие приборов (`K2636B.open()`, `PS.connect()`) выполнять **уже в worker-потоке** — через сигнал инициализации, обрабатываемый после старта потока. Открывать прибор до `moveToThread` (как в тесте референса) в рабочей программе нельзя: ресурс pyvisa окажется привязан к чужому потоку. (Решение подтверждено автором.)

## Завершение программы (порядок обязателен)

При закрытии окна (`MainWindow.closeEvent`):

1. Если идёт измерение — выполнить переход в `idle` с теми же действиями, что по команде stop (output=0, V=0, сохранение данных), без диалогов.
2. Выключить напряжение: output обоих каналов в 0, уровни V в 0 (защита образца и прибора).
3. Отправить в worker-поток команду на закрытие приборов (`K2636B.close()`, `PS.release()` — разомкнуть все реле).
4. `deviceThread.quit()`, `deviceThread.wait()` — дождаться фактического завершения потока.
5. Только после этого завершить приложение.

Пропуск шагов 2–4 недопустим: оставить прибор с включенным output или «повисший» поток при выходе — поломка железа или зависший процесс.

## Конечный автомат состояний измерения

Глобально три состояния:

| Состояние | Смысл |
|---|---|
| `idle` | измерения не было / оно завершено: этап задания параметров для последующих измерений; железо обесточено (output=0) |
| `measurements` | основной процесс: работают функции, объединяющие железо всех приборов, снимающих ВАХ на зондовой станции |
| `waiting` | режим ожидания: цикл остановлен, напряжение снято; просмотр промежуточных результатов (живой график); {корректировка параметров — по отдельному запросу} |

Все действия происходят не по состоянию, а по его изменению — **на переходах** (output, i_max, запуск/остановка цикла, сохранение, блокировка полей привязаны к переходам; состояние — только охрана переходов):

| Переход | Инициатор | Действия на переходе |
|---|---|---|
| idle → measurements | команда start | проверка параметров → создание папки образца (см. «Данные и сохранение») → {проверка коммутации PS} → установка i_max на приборе → output=1 → запуск цикла точек; все поля ввода блокируются |
| measurements → waiting | команда pause | цикл останавливается; **output=0** (напряжение с образца снимается — решение автора, безопасность образца) |
| waiting → measurements | команда resume | output=1, вернуть напряжение последней точки, **выждать delay** (чтобы напряжение установилось на образце), затем продолжить цикл |
| measurements/waiting → idle | команда stop ИЛИ естественный конец развёртки | output=0, V=0 → сохранение данных (.vac в папку образца) → сброс состояния, разблокировка полей, кнопка возвращается в «start»; живая кривая графика очищается, сохранённый файл сразу показывается из истории (см. history_widget.py) |
| measurements → idle | авария: измеренный ток достиг i_max | те же действия, что по stop (output=0, V=0, сохранение данных) + причина показывается в GUI (через startFailed) |

## MainWindow.py

Задача класса: отрисовать окно, в котором будут располагаться все остальные виджеты
Функции класса: 
1) при запуске main.py открывает виджеты K2636B_widget.py, controller_widget.py, PS_widget.py, history_widget.py и graph_widget.py
2) когда окно закрывается, закрываются все виджеты, открытые в нем и вся программа в целом — по процедуре из раздела «Завершение программы»
Комментарии: 
1) Графический интерфейс создается **программно, кодом на PySide6** (без Qt Designer и .ui-файлов) — главный критерий: просто и удобно дебажить. (Решение автора.)
2) ожидаемое расположение содержимого (см. схему `Test/shema_asp.jpg`): 
    1) масштабируемое окно
    2) столбец с виджетами **справа**, график — слева (решение автора, по схеме ментора)
    3) отношение сторон по длине +- 3 к 1 (3 - график, 1 - столбец)
    4) есть возможность регулировать соотношение графика и столбца по длине — засчет масштабирования графика (QSplitter), притом есть некоторый размер для виджетов, меньшего которого сделать нельзя (чтобы не поломать интерфейс)
    5) порядок виджетов в столбце сверху вниз: controller_widget (параметры + кнопки) → K2636B_widget (живые u, I) → PS_widget (контакты A, B) → «Оформление» (селектор темы) → history (история измерений, занимает всё оставшееся место колонки)
    6) каждый виджет (включая график) помещается в рамку QGroupBox с заголовком — визуальная группировка на фоне окна
    7) селектор темы оформления `theme_combo` (QComboBox: Светлая / Тёмная, палитры — в theme.py; тёмная — для работы в затемнённом помещении во время опытов): при смене эмитит сигнал `themeChanged(str)`; не блокируется никогда, в т.ч. по ходу измерения

Задача класса: запустить весь проект
Функции класса:
1) подгружает все составные модули проекта

## K2636B.py

Задача класса: связываться с прибором и актуализировать с него данные (логика single_responsibility)
Функции класса:
прямая связь с прибором через pyvisa. Живёт в worker-потоке. Развёртка идёт по **одному каналу** (A или B, по умолчанию A) — выбор приходит от пользователя, оба канала в драйвере доступны всегда.

Слоты (команды, вызываются из контроллера прямыми вызовами, из GUI — только через сигналы контроллера):
1) set_output_A(output: bool) / set_output_B(output: bool) — управляет статусом подключения к SMU-каналу измерительного прибора aka главный рубильник (через pyvisa); притом измерительных каналов - два - A и B.
**Output включается только на время измерения или дебага** (решение автора, чтобы избежать физических последствий): в `open()` оба канала остаются с `OUTPUT_OFF`.
здесь важно не забывать, что работаем с дорогостоящим оборудованием, поэтому требуется перепроверять статусы подключения (про output): после каждой установки output читать фактический статус с прибора (get_output_A/B) и сверять с запрошенным; при расхождении — сигнал ошибки
2) get_output_A() / get_output_B() -> bool — чтение фактического статуса output с прибора
3) set_voltage_A(voltage: float) / set_voltage_B(voltage: float) — получает данные от контроллера о напряжении, которое необходимо записать на K2636B
4) get_iv_A() / get_iv_B() -> tuple[float, float] — получает данные от измерительного прибора
5) set_i_max_A(limit: float) / set_i_max_B(limit: float) — ограничение тока (i_max) в амперах, защита образца; выставляется контроллером при старте измерения до включения output (SCPI-команда прибора — `smuX.source.limiti`, переименован только Python-интерфейс)
6) open() — открыть соединение; close() — закрыть. Вызываются только в worker-потоке (см. «Запуск потоков»)
7) debug-режим: если прибор не найден, драйвер переходит в режим симуляции (`simulated = True`) и генерирует правдоподобную ВАХ сам — основной способ разработки без железа

Сигналы (уведомления, на них подписываются виджеты и контроллер):
1) newIV_A(tuple) / newIV_B(tuple) — свежая пара (i, v); слушает ActualIV (подписка на канал, выбранный радиокнопкой)
2) newOut_A(bool) / newOut_B(bool) — фактический статус output
3) connectionLost — прибор перестал отвечать; контроллер обязан остановить измерение и выключить output

Комментарии: класс уже реализован, в файле /Automated-Probe-Station/reference/K2636B/K2636B.py
Предлаю взять этот файл за образец оформления {желательно в нем дописать Слоты для красоты}
Внимание: в референсе `open()` сразу включает output обоих каналов — в новой версии это убрать (см. решение автора выше).

## K2636B_widget.py (ActualIV)

Задача класса: отображать актуальные значения I V прибора в окне виджета
Функции класса:
1) это виджет, который интегрирован в MainWindow.py
2) показывает значения V (в строке: тип измеряемой величины, в чем измеряется, само значение)
3) показывает значения I (в строке: тип измеряемой величины, в чем измеряется, само значение - запись через экспоненту - ожидаются токи порядка пикоампер)
4) радиокнопки выбора канала **A / B** (по умолчанию A): виджет показывает значения выбранного канала и при смене эмитит сигнал `channelChanged(str)` — его слушает контроллер (развёртка идёт по выбранному каналу). Во время измерения выбор канала блокируется (слоты `lock()`/`unlock()` по сигналам контроллера startDone/stopDone/startFailed) — канал развёртки фиксируется на старте
5) данные получает напрямую подпиской на сигнал `K2636B.newIV_A` / `newIV_B` (см. правило 4 раздела «Многопоточность») — не через контроллер, чтобы живые значения не зависели от логики измерения

## controller_widget.py

Задача класса: задание базовых параметров измерения 
функции
1) отрисовывается widget с помощью pyside6 (программно, без .ui)
2) прописываются ячейки (весь функционал через Signal slot):
- номер образца (чтобы удобно было сохранять данные для серии экспериментов с образцом) — окно, заполняемое с клавиатуры; **до 15 символов**: латиница обоих регистров, цифры и символы `. _ -` (валидатор QRegularExpression в самом поле — ввести недопустимый символ невозможно). Набор сужен до безопасного для имени файла (проект работает в т.ч. на Windows-диске, где `/ \ : * ? " < > |` в именах запрещены) — решение автора. Имя образца = имя папки образца в рабочей директории (см. «Данные и сохранение»); в конфигах поля sample нет — во избежание конфликтов
- напряжение, с которого начинаем измерять V1: допустимый диапазон поля **[V_min; 0)**, жёсткий предел V_min задаётся в активном конфиге (limits, правится только из консоли; по умолчанию -40 В — защита от выгорания), значение по умолчанию **-1.000 В** (по схеме ментора)
- напряжение, которым заканчиваем измерять V2: допустимый диапазон **(0; V_max]**, предел V_max — из конфига (по умолчанию +40 В), значение по умолчанию **+1.000 В**
- шаг напряжения Vs (дробное положительное число, вольты; на схеме ментора пример 0.1 В). **Шаг стрелок полей V1 и V2 равен текущему Vs** (singleStep спинбоксов следует за Vs) — изменение V1/V2 стрелками всегда кратно шагу развёртки
- временной шаг Δt (чтобы необходимое напряжение установилось после его установке в виджете - по умолчанию 0; единицы — секунды)
- ограничение тока **i_max**, в амперах — редактируемое поле (решение автора; в коде и файлах данных повсюду имя `i_max`, термин «compliance» не используется); значение по умолчанию **10 мА** (0.01 А), допустимый диапазон поля 1 нА … i_max_limit (предел — из конфига, по умолчанию 100 мА); значение передаётся в контроллер и выставляется на приборе при старте до включения output. Если по ходу развёртки измеренный ток достигает i_max — экстренная остановка (см. controller.py)

- тип чипа (есть два варианта на выбор (OP2 и MD2) - никакой не идет по умолчанию). При смене типа чипа виджет эмитит сигнал `chipTypeChanged(str)` — на него подписывается ps_widget для обновления допустимого диапазона контактов
- радиокнопки масштаба графика: **линейный / логарифмический** (решение автора). При смене эмитит `scaleChanged(bool)` — слушает graph_widget.py
- кнопка "start", которая при первом нажатии превращается в "pause" при нажатии на "pause" превращается в "resume" и так далее по кругу с "pause", пока измерения не сбросят. **В idle кнопка неактивна, пока не заполнено имя образца**
- кнопка "stop" останавливает процессы, выставляет их в состояние по умолчанию, отправляет signal на сохранение данных. **Неактивна в idle** (нечего останавливать); активна и в measurements, и в waiting — измерение можно досрочно завершить в любой момент, включая паузу
- индикатор выполнения (прогресс-бар) **над кнопками start/stop**: процент выполнения развёртки по сигналу `progressUpdated(int)` контроллера (доля измеренных точек от плана — при постоянном темпе Δt это доля затраченного на измерения времени).
- значения и лимиты полей задаются **активным конфигом** (см. session.py): применяются при старте приложения, по сигналу `session.configChanged` (правки файла из консоли — слот `apply_config_safe`, во время измерения откладываются до stop) и при выборе образца с существующим local_config.json. Кнопок обмена с конфигом в GUI нет — из GUI в JSON не пишется ничего.

Сигналы виджета (все — в контроллер): sig_start(dict с полями sample, V1, V2, Vs, dt, chipType, i_max, scale, contactA, contactB, session_dir, limits), sig_pause(), sig_resume(), sig_stop(). Межвиджетные: chipTypeChanged(str), scaleChanged(bool).
Слоты виджета: on_started (заблокировать поля, кнопка → «pause», watcher — на local_config образца), on_paused/on_resumed (смена подписи кнопки), on_stopped (разблокировать поля, кнопка → «start», применить отложенный конфиг), on_start_failed(str) (показать причину отказа, остаться в idle), apply_config(dict), apply_config_safe(dict).

комментарии:
кнопки "start" и "stop" расположены рядом друг с другом, в ширину занимают то же расстояние, что и любая из ячеек с указанием данных
кнопка "start" направляет сигнал на установление output = 1, притом блокирует все ячейки, в которые возможно вмешательство извне. **Исключения** (доступны всегда, в т.ч. по ходу измерения): кнопки start/stop, график, радиокнопки масштаба лин/лог, селектор темы. Выбор канала A/B (K2636B_widget) блокируется отдельно — по сигналам startDone/stopDone/startFailed

## graph_widget.py (Graph)

Задача: отображать получаемые в ходе измерения экспериментальные точки на графике
функции:
1) создать виджет (на pyqtgraph — быстрый интерактивный график, заявлен в стеке проекта), подключить его к MainWindow
2) принимает значения (I, V) от контроллера (сигнал pointUpdated(u, i))
3) строит график: ось X — напряжение U (В), ось Y — ток I (А)
4) слот `set_log_scale(bool)` — переключение шкалы тока линейная / логарифмическая (по сигналу `scaleChanged` от controller_widget). Реализация — `setLogMode` оси Y pyqtgraph: меняется **только вид графика**, данные кривой не пересчитываются (решение ментора). Ограничение: в лог-режиме неположительные токи не отображаются — свойство логарифмической оси; радиокнопки масштаба доступны и по ходу измерения
5) жирные оси начала координат (U=0 и I=0 поверх сетки) — проще искать глазами; цвет — из темы оформления (слот `apply_theme(colors)` вызывается при смене темы, палитры — theme.py)
6) кривые истории: слоты `add_history_curve(name, u, i, color)` / `remove_history_curve(name)` — именованные кривые из .vac-файлов (см. history_widget.py) рисуются поверх живой кривой своими цветами из палитры, независимо от текущего измерения. PNG графика **не сохраняется** (упразднён)
7) при stop / новом старте очищается только **живая** кривая (слот `clear()`); кривые истории остаются на графике, пока их не снимут галочкой или не удалят файл. Очистка при stop не стирает измерение с экрана: в тот же момент история прожимает галочку свежего файла, и кривая перерисовывается из .vac (см. history_widget.py)

## controller.py

Задача класса: собирает сведения со всех основополагающих классов (PS.py, K2636B.py, graph_widget.py, controller_widget.py). Живёт в worker-потоке вместе с драйверами.
функции:
общие
1) прописывает логику измерения (неблокирующий цикл — см. раздел «Многопоточность»):
- исходной точкой напряжения является точка (0,0)
- измерение идет от исходной точки до максимума V2, от максимума до минимума V1, от минимума до исходной (чтобы в случае чего быть способным обнаружить гистерезис)
- на каждую точку: set_voltage → выдержка Δt (через QTimer, не sleep) → get_iv → emit pointUpdated
- после каждой точки эмитит progressUpdated(int) — процент выполнения развёртки (доля измеренных точек) для прогресс-бара controller_widget
- аварийная остановка по i_max: если измеренный |I| достиг ограничения i_max — экстренная остановка: сброс напряжения (output=0, V=0), сохранение уже измеренных данных (как при stop), причина «Экстренная остановка: |I| достиг i_max» отправляется в GUI через startFailed (тот же канал, что для потери связи и ошибок прибора)
- развёртка идёт по каналу, выбранному в ActualIV (сигнал `channelChanged` → слот `set_channel`, по умолчанию A)
2) ведёт конечный автомат состояний idle/measurements/waiting (таблица переходов — в разделе «Многопоточность»; на паузе output=0, на resume — восстановление напряжения с выдержкой delay)
3) хранит данные эксперимента (параметры + массивы точек) и при завершении сохраняет их в файл **.vac** (JSON внутри) в папку образца — только контроллер обладает всей полнотой данных, поэтому сохранение данных именно его обязанность

для controller_widget:
1) получает параметры измерения (sig_start с dict)
2) обменивается статусом output (через startDone/startFailed/stopDone и сигналы драйвера newOut_*)

Слоты: start(dict), pause(), resume(), stop(), set_channel(str).
Сигналы: startDone, startFailed(str), pauseDone, resumeDone, stopDone(str — путь к сохранённому .vac), pointUpdated(u, i), progressUpdated(int), finished (естественный конец развёртки — тоже приводит к сохранению и переходу в idle).

## PS.py

Задача: подключиться к измерительной станции. Живёт в worker-потоке.
функции:
1) на этом этапе быть заглушкой, чтобы можно было проверить ее подключение к контроллеру и к переключаемым контактам
2) не ломать программу
3) интерфейс заглушки должен совпадать с будущим реальным драйвером, чтобы замена прошла без правок контроллера:
   - set_contacts(a: int, b: int) -> bool — скоммутировать пару контактов; возвращает True только после подтверждения коммутации (в заглушке — всегда True)
   - release() — разомкнуть все реле
   - сигналы: contactsChanged(a, b), released, error(str)
4) правило безопасности на будущее (уже заложить в контроллер): напряжение (output=1) подаётся только после того, как set_contacts вернул True; при False — старт отклоняется сигналом startFailed

## PS_widget.py (PSWidget)

задача: настроить доступ к подключаемым контактам, которые будут проверять ВАХ на образце чипа
функции:
1) отрисовать виджет, подключить его к MainWindow
2) выпадающий список (QComboBox), слева от него подпись A — номер контакта от 1 до 15 для MD2 и от 1 до 13 для OP2 (выбор из списка, без ручного ввода и прокликивания). Меню списка сворачивается сразу после выбора варианта (нативное поведение QComboBox, как у селектора темы)
3) выпадающий список (QComboBox), слева от него подпись B — аналогично
   (утверждено автором: MD2 — 30 контактов, по 15 на стороны A и B; OP2 — 26 контактов, по 13 на стороны A и B)
4) списки наполняются значениями по сигналу `chipTypeChanged` от controller_widget (слот `set_chip_type(str)`); пока тип чипа не выбран — списки недоступны
5) выбранные контакты включаются в dict параметров при старте измерения (поля contactA, contactB)
6) слот `set_contacts(a, b)` — выставить контакты извне (применение конфига); значения вне диапазона текущего чипа игнорируются

## session.py

Задача класса: рабочая папка и её конфигурационные файлы. Живёт в GUI-потоке (создаётся в main.py).
функции:
1) **рабочая папка** (workdir) — корень данных запуска. По умолчанию `demo/data/` (константа `DEFAULT_WORKDIR` — **место, где меняется параметр сохранения по умолчанию**); переопределяется аргументом `-d` (короткое имя — подпапка `demo/data/<имя>/`, абсолютный путь — как есть), последней выбранной в GUI папкой (QSettings) и кнопкой «Рабочая папка…» в истории (`set_workdir(dir)` — на ходу)
2) при входе в рабочую папку (старт приложения или смена) в ней создаётся `config.json` из встроенных дефолтов, если его нет — **скелет параметров измерения**
3) `sample_dir(sample)` — папка образца `<workdir>/<sample>/`: создаётся **при нажатии start** (не при запуске программы); при первом создании внутрь кладётся `local_config.json` — копия config.json. Существующая папка пополняется, ничего не удаляется
4) `read_config(path=None)` — прочитать конфиг; битый или неполный файл дополняется встроенными дефолтами (без падения)
5) `set_active_config(path)` — переключить активный конфиг (local_config.json текущего образца / выбранной «основной» папки, иначе config.json рабочей папки). За активным конфигом следит **QFileSystemWatcher**: правка файла из консоли → сигнал `configChanged(dict)` → GUI подтягивает значения (в idle; во время измерения — отложенно, применяются после stop). Обратной записи из GUI в JSON нет

Схема config.json и local_config.json (одинаковая; правятся из консоли):
- `values` — рабочие значения полей GUI (V1, V2, Vs, dt, i_max, chipType, contactA, contactB, scale). Поля `sample` в конфигах **нет** — имя образца живёт только в GUI и именах файлов/папок (во избежание конфликтов)
- `limits` — жёсткие границы полей (V_min, V_max, Vs_min, Vs_max, dt_min, dt_max, i_max_limit); применяются к диапазонам спинбоксов при применении конфига. Так для напряжения существует 4 величины: два предельных значения (limits, только консоль) и два рабочих (V1/V2 — отрезок измерения внутри лимитов, GUI); аналогично для тока (i_max_limit / i_max) и остальных величин

Сигналы: configChanged(dict).

## history_widget.py (History)

Задача класса: виджет истории измерений в правой колонке (занимает всё оставшееся место, список прокручивается). Живёт в GUI-потоке, во время измерения **не блокируется**.
функции:
1) **плашка поиска** (QLineEdit) над деревом: подстрочный регистронезависимый фильтр папок (видна, если совпало имя папки или имя уже отсканированного .vac внутри; пример: `DD05` находит `DD051`, `tebwrbwt_DD05`)
2) дерево (QTreeWidget) рабочей папки: верхний уровень — папки и .vac-файлы верхнего уровня; **папки добавляются без сканирования вглубь** (ленивые блоки с плейсхолдером «…») — содержимое (.vac + подпапки, тоже ленивые) читается при раскрытии блока, выстраиваясь веточным ветвлением. Порядок: основная папка наверху, остальные по алфавиту
3) кнопки: «Добавить папку…» (QFileDialog — показать произвольную папку блоком) и «Рабочая папка…» (смена рабочей папки на ходу: дерево перестраивается, сигнал `workdirChanged(str)` → session + QSettings)
4) контекстное меню (правая кнопка) папки: **«Сделать основной»** (блок поднимается наверх, прежняя основная уходит в алфавитную сортировку; сигнал `primaryChanged(dir)` — watcher session переключается на её local_config.json, если есть), **«Удалить из Истории»** (папка убирается из дерева, с диска ничего не удаляется) и **«Открыть в проводнике»** (папка открывается в файловом менеджере ОС, QDesktopServices)
5) контекстное меню файла: **«Удалить с устройства»** — удаление с диска **с обязательным подтверждением** (модальный QMessageBox); кривая файла снимается с графика. Логика удаления вынесена в `_delete(paths)` без диалога — для тестирования
6) слот `on_measurement_saved(path)` — по сигналу `stopDone` свежий .vac появляется первым в своём блоке, блок поднимается наверх и раскрывается, **галочка прожимается автоматически**: живая кривая в этот момент очищается (stopDone → graph.clear), и измерение сразу показывается из файла — визуально график не пропадает, меняется способ отображения
7) чекбокс файла → сигнал `curveToggled(path, on, color)`: кривая строится по точкам из .vac поверх живого графика, независимо от текущего измерения; цвет — из генерируемой палитры (pg.intColor), за файлом закрепляется; отмеченный файл получает цветной квадрат-иконку в списке
8) битый .vac (не JSON / нет массивов) не роняет программу: файл помечается подписью «(ошибка)», галочка снимается

Сигналы: curveToggled(str, bool, QColor), primaryChanged(str), workdirChanged(str).
Слоты: on_measurement_saved(str), add_file(str), mark_error(str), set_workdir(str).

# Данные и сохранение

1) Данные эксперимента сохраняет контроллер при завершении (stop, естественный конец развёртки или авария i_max).
2) **Рабочая папка** — корень данных. По умолчанию `demo/data/` (в .gitignore; константа `DEFAULT_WORKDIR` в session.py — место, где меняется параметр сохранения по умолчанию). Выбор: `make run d=<имя>` (подпапка `demo/data/<имя>/`), `make run d=<абсолютный путь>` (произвольная папка), кнопка «Рабочая папка…» в истории (запоминается в QSettings — действует при следующих запусках). Приоритет при запуске: `-d` → QSettings → `demo/data/`.
3) В рабочей папке лежит `config.json` (скелет параметров, создаётся из дефолтов кода) и папки образцов. Папка образца `<workdir>/<sample>/` создаётся **при нажатии start**; смена имени образца → новая папка; существующая пополняется, ничего не удаляется. Внутри:
   - `local_config.json` — конфиг образца (создаётся копией config.json при первом старте этого образца; дальше регламентирует параметры — правится из консоли, подтягивается в GUI автоматически)
   - файлы `.vac` — результаты измерений этого образца
4) Имя .vac по шаблону `YYYY-MM-DD_HH-MM-SS_<номер образца>_A<NN>_B<NN>.vac` — дата-время, образец, контакты A и B (две цифры с ведущим нулём, напр. `A03_B04`). При совпадении имени в пределах одной секунды — суффикс `_1`, `_2`, …
5) .vac — это JSON: параметры измерения (sample, chipType, V1, V2, Vs, dt, i_max, channel, contactA, contactB), массивы точек u/i и метка saved_at. Файл самодостаточен — содержит всё для повторения эксперимента. Ключ `i_max` — после повсеместной замены термина compliance; файлы, сохранённые до переименования, по этому ключу несовместимы. (Расширение `.vag` упразднено в пользу `.vac`, содержимое не изменилось.)
6) CSV и PNG графика **не создаются** (упразднены: данные для сторонних программ читаются из .vac как из обычного JSON).
7) По окончании измерения (stop / конец развёртки / авария) живая кривая графика очищается, а сохранённый файл появляется в истории с прожатой галочкой — измерение сразу показывается из файла.
